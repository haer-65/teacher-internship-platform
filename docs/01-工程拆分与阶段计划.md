## A. 整体工程拆分方案

### 1) 仓库与工程边界
采用同仓多目录（前后端分离，单体后端）：

```text
teacher-internship-platform/
├─ frontend/          # Vue3 + TS + Vite 前端工程
├─ backend/           # Spring Boot 单体后端工程
├─ sql/               # 建表脚本、初始化数据、迁移脚本
├─ docs/              # 需求、设计、接口、迭代文档
├─ tools/             # 本地启动脚本、导入导出脚本、辅助工具
├─ uploads/           # 本地文件存储目录（运行期）
└─ temp/              # 临时文件目录（非发布）
```

### 2) 运行架构（本地开发）
- 前端：`5173`（Vite）
- 后端：`8080`（Spring Boot）
- MySQL：`3306`
- Redis：`6379`
- 文件目录：`D:\teacher-internship-platform\uploads`

### 3) 技术分层
- 前端层：页面、路由、状态管理、API 封装、权限显隐。
- 后端层：认证鉴权、业务编排、事务、数据访问、文件访问鉴权、审计日志。
- 数据层：MySQL 持久化 + Redis 缓存。
- 文件层：本地目录存储，数据库仅保存元数据与相对路径。

### 4) 固定开发流程（每个模块）
1. 先骨架（目录、枚举、DTO、接口占位）
2. 再数据库（表结构、索引、初始化字典）
3. 再后端接口（Controller/Service/Mapper）
4. 再前端页面（API 封装 -> 页面 -> 交互）
5. 最后联调与回归（权限、状态流转、边界条件）

## D. 核心模块划分

### P0（必须先完成）
1. `auth`：登录、登出、角色切换、首登改密、JWT 刷新策略。
2. `system`：用户、角色、菜单/权限、密码重置、操作日志。
3. `base`：院系、专业、年级、班级、实习基地等基础主数据。
4. `plan`：实习计划、状态流转、材料规则、评分权重、计划附件。
5. `application`：学生申请、审核、手动/批量分配、分配调整留痕。
6. `material`：材料主记录、版本记录、上传/预览/下载、逾期控制。
7. `evaluation`：过程评价、综合评价、评语与评分留痕。
8. `score`：成绩计算、人工调整、发布、成绩单导出。

### P1（P0 跑通后）
1. `notice`：站内消息、已读未读、关键事件触发。
2. `stats`：提交率、评价率、成绩分布、报表导出。
3. `system` 扩展：参数配置、审计查询增强、批量导入导出。

## E. 开发阶段计划（可执行）

### 阶段 0：工程初始化（0.5 周）
- 前后端脚手架初始化。
- 统一代码规范、目录骨架、环境变量模板。
- 统一接口返回结构、全局异常、分页对象。
- 完成开发环境连通（MySQL/Redis/文件目录）。

### 阶段 1：权限与基础能力（1 周）
- 完成 `auth + system + base` 后端基础接口。
- 完成登录页、路由守卫、动态菜单、权限码控制。
- 完成用户/角色/基础数据最小管理页面。
- 验收：登录、鉴权、数据范围过滤可跑通。

### 阶段 2：计划与申请分配（1.5 周）
- 完成 `plan` 模块接口与页面。
- 完成 `application` 模块（申请、审核、分配、导入）。
- 计划发布 -> 学生申请 -> 分配结果链路打通。
- 验收：主流程前半段闭环可演示。

### 阶段 3：材料与评价（1.5 周）
- 完成 `material` 模块（版本化、文件鉴权访问、补交控制）。
- 完成 `evaluation` 模块（过程评价+综合评价）。
- 验收：材料版本追溯、评价记录留痕可验证。

### 阶段 4：成绩闭环（1 周）
- 完成 `score` 模块（自动计算、人工调整、发布、导出）。
- 接通评价结果到成绩计算。
- 验收：计划发布 -> 申请分配 -> 材料 -> 评价 -> 成绩发布全闭环。

### 阶段 5：P1 增强（1 周）
- 完成 `notice`、`stats`、`sys_param`、日志审计增强。
- 完成关键看板与导出能力。
- 验收：管理端可查看关键统计，消息提醒可用。

### 阶段 6：联调、测试、交付（0.5 周）
- 全角色联调、越权测试、边界测试、回归测试。
- 输出部署文档、接口文档、测试报告、初始化 SQL。

## F. 需要先落库的核心表清单

按“阻塞程度”排序，先建第一批（阻塞 P0），再建第二批（P1）。

### 第一批（P0 必建）
1. `sys_user`：用户主表（学生学号/教师工号、状态、改密标记）。
2. `sys_role`：角色定义（6 个固定角色）。
3. `sys_user_role`：用户-角色关联。
4. `sys_menu`：菜单与权限码。
5. `sys_role_menu`：角色-菜单权限关联。
6. `base_department`：院系。
7. `base_major`：专业。
8. `base_grade`：年级。
9. `base_class`：班级。
10. `base_internship_base`：实习基地。
11. `biz_internship_plan`：实习计划。
12. `biz_plan_attachment`：计划附件。
13. `biz_material_type`：材料类型与截止规则。
14. `biz_student_application`：学生申请。
15. `biz_assignment`：分配结果（基地+双导师）。
16. `biz_material`：材料主表（按分配+材料类型聚合）。
17. `biz_material_version`：材料版本表。
18. `biz_evaluation`：过程/综合评价记录。
19. `biz_score_sheet`：成绩单（自动计算+人工调整留痕字段）。
20. `sys_login_log`：登录日志。
21. `sys_operation_log`：关键操作日志。

### 第二批（P1 建表）
1. `biz_notice`：站内消息主表。
2. `biz_notice_receiver`：消息接收与已读状态。
3. `sys_param`：系统参数表。
4. `biz_export_task`（可选）：大报表导出任务记录。

### 必加唯一约束（核心）
- `sys_user.login_name` 唯一。
- `biz_student_application (plan_id, student_id)` 唯一。
- `biz_assignment (plan_id, student_id)` 唯一（仅一条当前有效分配）。
- `biz_material (assignment_id, material_type_id)` 唯一。
- `biz_material_version (material_id, version_no)` 唯一。
- `biz_score_sheet (plan_id, student_id)` 唯一。

## G. 模块先后依赖关系

### 1) 强依赖链（必须顺序）
1. `auth/system` -> 2. `base` -> 3. `plan` -> 4. `application` -> 5. `assignment` -> 6. `material` -> 7. `evaluation` -> 8. `score`

### 2) 可并行模块
- `notice` 可在阶段 3 后并行接入（监听计划发布、分配、评价、成绩事件）。
- `stats` 需在 `score` 稳定后开发，否则口径不稳定。
- `sys_param`、`日志检索页` 可与 `notice/stats` 并行。

### 3) 依赖说明（关键）
- `plan` 依赖 `base_department` 与角色权限。
- `application` 依赖 `plan` + 学生账号。
- `assignment` 依赖 `application` + 基地 + 双导师账号。
- `material` 依赖 `assignment` + `material_type`。
- `evaluation` 依赖 `material_version`（过程评价）与 `assignment`（综合评价）。
- `score` 依赖 `evaluation` + 计划权重配置。
- `stats` 依赖 `plan/application/material/evaluation/score` 全链路数据。

## 本轮后续执行约束（固定）
- 所有接口遵循：`/api/v1/{module}/{action}`，统一响应 `{ code, message, data }`。
- 分页参数固定：`page`、`size`。
- 鉴权头固定：`Authorization: Bearer <token>`。
- 上传固定：`multipart/form-data`。
- 时间固定：`yyyy-MM-dd HH:mm:ss`。
- 任何关键业务（申请、分配、材料版本、评价、成绩调整、密码重置、权限变更）必须留痕可追溯。
