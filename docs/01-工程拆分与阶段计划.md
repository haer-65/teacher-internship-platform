# 工程拆分与阶段计划

本文档用于说明平台的工程拆分方式、模块边界和交付节奏。当前项目已经开发完成，因此这里按“已交付版本”来整理，而不是按未完成计划来写。

## 1. 当前交付状态

平台已经覆盖以下完整业务链路：
- 登录认证、角色切换和权限控制
- 实习计划创建、编辑、发布、归档
- 学生申请、审核、手动分配、批量导入分配
- 过程材料上传、版本管理、重提控制
- 过程评价、综合评价、评价留痕
- 成绩计算、人工调整、发布、导出
- 站内通知、到期提醒、消息读取状态
- 统计分析、系统用户、RBAC、基础数据和参数管理

## 2. 工程边界

```text
teacher-internship-platform/
├─ frontend/   # Vue3 + TypeScript 前端
├─ backend/    # Spring Boot 后端
├─ sql/       # 数据库初始化与迁移脚本副本
├─ docs/      # 交付和使用文档
├─ tools/     # Windows 本地依赖、启动和检查脚本
└─ uploads/   # 文件上传目录
```

## 3. 模块拆分

### 3.1 认证与系统底座

- `auth`：登录、退出、当前用户信息、角色切换
- `system`：用户管理、角色权限、菜单、参数、日志、基础数据
- `base`：院系、专业、年级、实习基地等基础字典和下拉选项

### 3.2 实习业务主链路

- `plan`：实习计划、附件、材料要求、学生可见计划
- `application`：学生申请、审核、分配、导入、调整
- `material`：过程材料、版本记录、预览、下载、重提控制
- `evaluation`：过程评价和综合评价
- `score`：成绩计算、调整、发布、导出

### 3.3 扩展能力

- `notice`：站内通知、未读数、手动发送、到期提醒
- `stats`：过程和结果统计、维度分析、导出

## 4. 推荐开发顺序

即使项目已经完成，这个顺序仍然适合后续迭代：

1. 认证与权限
2. 基础数据和系统管理
3. 实习计划
4. 申请与分配
5. 材料管理
6. 评价管理
7. 成绩管理
8. 通知与统计

## 5. 核心约束

- 所有业务接口统一走 `/api/v1/{module}/...`
- 前端页面统一通过 `src/api/modules/*` 调用接口
- 文件上传统一使用 `multipart/form-data`
- 时间展示和请求统一使用 `yyyy-MM-dd HH:mm:ss`
- 业务状态、角色、身份类型等统一使用枚举或常量

## 6. 业务闭环

平台的主闭环可以概括为：

1. 管理员配置基础数据和实习计划。
2. 学生提交申请，管理员审核并分配指导教师。
3. 学生按计划提交过程材料，教师查看并评价。
4. 系统计算成绩，管理员或教师完成确认和发布。
5. 通知模块同步关键节点，统计模块输出过程和结果数据。
