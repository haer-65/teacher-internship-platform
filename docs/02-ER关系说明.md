# ER 关系说明

本文档描述当前平台的核心实体关系，方便理解数据流向和业务闭环。

## 1. 用户与权限域

### 1.1 用户表

- `sys_user`：平台用户主表，保存登录账号、身份类型、学号/工号、联系方式、所属院系/专业/年级等信息。
- `sys_role`：角色表，包含系统管理员、院系管理员、教务管理员、校内指导教师、基地指导教师、学生等角色。
- `sys_user_role`：用户与角色的多对多关系表。

### 1.2 菜单与权限

- `sys_menu`：菜单和权限点定义。
- `sys_role_menu`：角色与菜单/权限点的关联表。

### 1.3 配套系统表

- `sys_param`：系统参数
- `sys_operation_log`：操作日志
- `sys_login_log`：登录日志

## 2. 基础数据域

- `base_department`：院系
- `base_major`：专业
- `base_grade`：年级
- `base_internship_base`：实习基地

这些表为用户、计划和分配提供下拉数据和业务过滤条件。

## 3. 实习计划域

- `biz_plan_base`：计划公共基底信息，例如院系、专业、年级、计划学期等适用范围。
- `biz_internship_plan`：实习计划主表，保存标题、说明、状态、时间范围、名额、权重配置等。
- `biz_plan_attachment`：计划附件表，保存上传的说明文档、模板和补充材料。
- `biz_material_type`：计划对应的材料类型配置，决定学生需要提交哪些材料。

关系上：
- 一个 `biz_plan_base` 可以对应多个计划。
- 一个 `biz_internship_plan` 可以挂多个附件和多个材料类型。

## 4. 申请与分配域

- `biz_student_application`：学生申请表，一个学生对一个计划只能有一条主申请记录。
- `biz_application_preference`：申请偏好表，用于记录学生的基地、方向或补充偏好。
- `biz_assignment`：分配记录表，保存学生、校内指导教师、基地指导教师、版本号和当前生效记录。

关系上：
- 一个计划下可以有多条申请。
- 一条申请可以产生多次分配版本。
- 分配是后续材料、评价和成绩的上游主键来源。

## 5. 材料与评价域

- `biz_material`：学生提交的过程材料主表。
- `biz_material_version`：材料版本表，用于记录每次上传、重提和历史版本。
- `biz_material_resubmit_control`：重提控制表，用于管理材料是否允许再次提交。
- `biz_evaluation`：评价记录表，覆盖过程评价和综合评价。

关系上：
- 一个学生在一个计划下会产生多条材料记录和多个版本。
- 评价记录通常围绕“计划 + 学生 + 教师 + 评价类型”展开。

## 6. 成绩域

- `biz_score_sheet`：成绩表，保存最终成绩、权重拆分、调整痕迹、发布状态和导出数据。

关系上：
- 成绩通常从计划、分配、评价和材料数据汇总生成。
- 一条成绩记录对应一个学生在一个计划下的最终结果。

## 7. 通知域

- `biz_notice`：通知主表。
- `biz_notice_receiver`：通知接收人表。

通知数据与计划、申请、材料、评价和成绩的关键动作联动，用于站内消息和未读统计。

## 8. 业务主链路

平台的主链路可以概括为：

```text
基础数据 -> 实习计划 -> 学生申请 -> 审核分配 -> 材料提交 -> 过程/综合评价 -> 成绩计算 -> 成绩发布 -> 通知与统计
```

其中：
- 计划是入口
- 申请和分配是承接
- 材料和评价是过程
- 成绩和通知是结果
