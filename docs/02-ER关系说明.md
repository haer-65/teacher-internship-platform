# ER 关系说明（P0 + P1 基础）

## 1. 核心域分层
- 系统域：`sys_*`（用户、角色、菜单、权限、参数、日志）
- 基础数据域：`base_*`（院系、专业、年级、实习基地）
- 实习业务域：`biz_*`（计划、申请、分配、材料、评价、成绩、通知）

## 2. 关键关系

### 2.1 用户权限
- `sys_user` 与 `sys_role`：多对多，通过 `sys_user_role` 关联
- `sys_role` 与 `sys_menu`：多对多，通过 `sys_role_menu` 关联

### 2.2 基础数据
- `base_department` 与 `base_major`：一对多
- `sys_user` 可关联 `base_department/base_major/base_grade`

### 2.3 实习主链路
- `biz_internship_plan`（计划）与 `biz_material_type`（材料类型）：一对多
- `biz_internship_plan` 与 `biz_student_application`（学生申请）：一对多
- `biz_student_application` 通过审核后形成 `biz_assignment`（分配）
- `biz_assignment` 与 `biz_material`（材料主表）：一对多（按材料类型聚合）
- `biz_material` 与 `biz_material_version`（材料版本）：一对多（重复上传生成新版本）
- `biz_evaluation` 通过 `material_version_id` 绑定到材料版本
- `biz_score_sheet` 以 `(plan_id, student_id)` 作为唯一成绩单聚合单元

### 2.4 通知与日志
- `biz_notice` 与 `sys_user`（发送人）：多对一
- `biz_notice` 与 `sys_user`（接收人）：多对多，通过 `biz_notice_receiver`
- `sys_login_log`、`sys_operation_log` 分别记录登录与关键操作审计

## 3. 业务约束在模型中的落地
- 同一学生同一计划仅允许一条有效申请：`biz_student_application` 唯一约束 `(plan_id, student_id, deleted)`
- 材料主表与版本表分离：`biz_material` + `biz_material_version`
- 评价记录与材料版本绑定：`biz_evaluation.material_version_id` 非空外键
- 成绩按计划+学生唯一：`biz_score_sheet` 唯一约束 `(plan_id, student_id, deleted)`
- 通知多对多接收：`biz_notice_receiver` 唯一约束 `(notice_id, receiver_id, deleted)`
- 全表统一审计与逻辑删除：`created_by/created_time/updated_by/updated_time/deleted`
